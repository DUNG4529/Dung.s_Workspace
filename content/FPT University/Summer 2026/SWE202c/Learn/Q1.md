# Question 1.1: Identify and justify the SDLC model (1.0 points)

I choose **Agile (Scrum)** as the most suitable SDLC model for the **<Điền tên hệ thống trong đề - VD: Course Registration System (CRS)>**. The main reason is that the characteristics of this project match the strengths of Agile in terms of flexibility, iterative development, and continuous stakeholder involvement.

### 1. Requirements are not completely fixed

Although the organization is already operating with a **<Điền quy trình cũ đang dùng - VD: paper-based manual process>**, only the overall business process is clear. Since this is a brand-new software system, many details such as UI/UX, workflows, and user expectations may change after users start using the product.

Because Agile accepts requirement changes throughout development, it is more suitable than a rigid development model.

### 2. Continuous feedback from stakeholders

The system is designed for different groups of users, including **<Liệt kê 3-4 nhóm user trong đề - VD: Students, Lecturers, Academic Staff, System Admin>**.

Instead of delivering the whole system at once, Agile divides development into multiple Sprints. After each Sprint, stakeholders can review the working product, provide feedback, and request necessary adjustments. This helps ensure that the final system better satisfies actual business needs.

### 3. Better management of project risks

The project contains several important technical challenges, such as:

- **<Liệt kê rủi ro 1 từ đề - VD: handle 1,000 concurrent users with < 3s response time>**
- **<Liệt kê rủi ro 2 từ đề - VD: secure sensitive data using TLS 1.2+ and RBAC>**

Agile allows the team to develop MVPs early and perform performance or security testing from the first few Sprints. As a result, technical problems can be detected and resolved much earlier instead of waiting until the end of the project.

### 4. Suitable for the project scale

The project is expected to serve **<Quy mô từ đề - VD: 8,000 students>**, so development should be organized into smaller iterations to reduce workload and improve progress tracking.

Even if **<Tên tổ chức trong đề - VD: University>** follows a formal change-control process, Agile still supports this through Sprint Planning and Sprint Review meetings, where every requested change can be discussed, approved, and tracked systematically.

# Question 1.2: Alternative model and comparison (1.0 points)

Besides Agile (Scrum), another possible SDLC model is the **Waterfall Model**. Below is a comparison between the two models for the **<Điền tên hệ thống>** project.

## A. Agile (Scrum) - Selected Model

### Advantages

1. Detects and reduces technical risks early through continuous testing during every Sprint, especially risks such as **<Nhắc lại 1 rủi ro kỹ thuật - VD: server overload during peak registration>**.
2. Allows the team to respond quickly to changing requirements and feedback from **<Nhắc lại 1 nhóm user - VD: Students>**, resulting in a system that better matches user expectations.

### Disadvantages

1. Requires the Product Owner (**<Tên tổ chức - VD: University administration>**) to participate regularly in Sprint reviews and provide continuous feedback.
2. Since requirements may change throughout development, it is harder to estimate the final project cost and completion date at the beginning.

---

## B. Waterfall - Alternative Model

### Advantages

1. Produces detailed documentation before development starts, making it suitable for organizations such as **<Tên tổ chức - VD: University>** where documentation is important.
2. Defines the overall schedule and project budget from the beginning, making project planning easier.

### Disadvantages

1. If a major issue appears during final integration or load testing, such as **<Nhắc lại rủi ro chịu tải - VD: 1,000 concurrent users>**, fixing the architecture at that stage can be expensive and time-consuming.
2. Users such as **<Nhắc lại 1 nhóm user - VD: Lecturers>** cannot evaluate the system until development is almost finished, increasing the risk that the final product does not fully meet their expectations.
