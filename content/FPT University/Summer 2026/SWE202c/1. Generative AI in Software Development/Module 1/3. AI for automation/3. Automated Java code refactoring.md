# Tự Động Hóa Refactoring Code Với Amazon Q Developer

## Giới Thiệu

Quản lý ứng dụng Java cho hệ thống quản lý khoản vay có thể trở nên khó khăn khi hệ thống mở rộng. Trạng thái khoản vay như *APPROVED*, *PENDING* và *REJECTED* thường được xử lý bằng **switch statements**. Mặc dù cách tiếp cận này hoạt động ban đầu, nhưng theo thời gian nó có thể dẫn đến code dài dòng, lặp lại và dễ phát sinh lỗi. Việc cập nhật hoặc thêm trạng thái mới trở nên tẻ nhạt và tăng nguy cơ bug.

Điều này nhấn mạnh tầm quan trọng của code sạch, dễ bảo trì. Tuy nhiên, việc tự tay refactor các cấu trúc phức tạp rất tốn thời gian. Đó là lúc **Amazon Q Developer** xuất hiện – một công cụ AI được thiết kế để tự động hóa quá trình refactoring code, giúp code của bạn sạch hơn, hiệu quả hơn và dễ bảo trì hơn.

Bài đọc này sẽ hướng dẫn bạn cách Amazon Q Developer chuyển đổi code lặp lại, như switch statements, thành các cấu trúc dựa trên **enum** hiệu quả. Bạn sẽ học cách:
- Cải thiện khả năng đọc code
- Giảm rủi ro bảo trì
- Nâng cao khả năng mở rộng

---

## Quy Trình 4 Bước Với Amazon Q Developer

### Bước 1: Explain Code (Giải Thích Code)

Khi gặp một đoạn code không quen thuộc hoặc được kế thừa — như một switch statement dài xử lý trạng thái khoản vay — điều cần thiết là hiểu mục đích của nó trước.

**Tính năng Explain Code** của Amazon Q Developer cung cấp mô tả rõ ràng, chi tiết về chức năng của code chỉ với một lệnh đơn giản, giúp bạn tiết kiệm thời gian và công sức.

**Lợi ích:**
- Hiểu nhanh cấu trúc và mục đích của code
- Đặc biệt hữu ích trong các team lớn hoặc khi bảo trì legacy codebases

---

### Bước 2: Refactor Code (Cấu Trúc Lại Code)

Sau khi hiểu code, bước tiếp theo là cải thiện cấu trúc của nó.

**Tính năng Refactor Code** của Amazon Q Developer xác định cơ hội để tối ưu hóa switch statement bằng cách chuyển đổi nó thành **enum**. Mỗi trạng thái khoản vay được biểu diễn dưới dạng một constant với các hành động liên kết, giúp code sạch hơn và dễ quản lý hơn.

**Lợi ích của Enum:**
- Giảm redundancy (trùng lặp)
- Tổ chức các hành động liên quan trong một cấu trúc duy nhất
- Dễ dàng thêm hoặc sửa đổi trạng thái

---

### Bước 3: Fix Code (Sửa Lỗi)

Trong quá trình kiểm thử, các tình huống chưa được xử lý (như unknown statuses) có thể gây ra exceptions.

**Tính năng Fix Code** của Amazon Q Developer xác định các vấn đề như vậy và đề xuất giải pháp, ví dụ như thêm error handling để ngăn crash.

**Ví dụ lỗi:**
Code không xử lý trường hợp nhận được status không hợp lệ → gây exception.

**Sửa lỗi:**
Thêm `try-catch` block để bắt exception và xử lý hợp lý.

```java
try {
    // Process loan status
} catch (IllegalArgumentException e) {
    System.out.println("Unknown loan status!");
}
```

---

### Bước 4: Optimize Code (Tối Ưu Hóa)

Sau khi code hoạt động chính xác, đã đến lúc tối ưu hiệu suất.

**Tính năng Optimize Code** đề xuất các cải tiến như giảm redundancy hoặc tăng hiệu quả.

**Ví dụ tối ưu:**
Thêm method `getMessage()` để cache status message, tránh lặp lại khi truy cập nhiều lần.

```java
public enum LoanStatus {
    APPROVED {
        public String getMessage() {
            return "Loan has been approved.";
        }
    },
    PENDING {
        public String getMessage() {
            return "Loan is pending review.";
        }
    },
    REJECTED {
        public String getMessage() {
            return "Loan has been rejected.";
        }
    };
    
    public abstract String getMessage();
}
```

**Kết quả:** Code hiệu quả hơn mà không thay đổi chức năng.

## So Sánh Code Trước Và Sau Khi Refactor

### Code Gốc (Sử Dụng Switch Statement)

```java
public class LoanProcessor {
    public void processStatus(String status) {
        switch(status) {
            case "APPROVED":
                System.out.println("Loan approved!");
                break;
            case "PENDING":
                System.out.println("Loan pending...");
                break;
            case "REJECTED":
                System.out.println("Loan rejected.");
                break;
            default:
                System.out.println("Unknown status.");
        }
    }
}
```

**Nhược điểm:**
- Dài dòng
- Khó thêm trạng thái mới
- Dễ quên cập nhật tất cả các nơi sử dụng

### Code Sau Khi Refactor (Sử Dụng Enum)

```java
public enum LoanStatus {
    APPROVED {
        public void process() {
            System.out.println("Loan approved!");
        }
    },
    PENDING {
        public void process() {
            System.out.println("Loan pending...");
        }
    },
    REJECTED {
        public void process() {
            System.out.println("Loan rejected.");
        }
    };
    
    public abstract void process();
}

public class LoanProcessor {
    public void processStatus(String status) {
        try {
            LoanStatus.valueOf(status).process();
        } catch (IllegalArgumentException e) {
            System.out.println("Unknown status.");
        }
    }
}
```

**Ưu điểm:**
- Code ngắn gọn, rõ ràng
- Dễ thêm trạng thái mới (chỉ thêm constant mới)
- Tất cả logic liên quan tập trung trong enum
- Dễ bảo trì và mở rộng

## Bài Tập Thực Hành: Cải Thiện Discount Calculator

### Tình Huống

Bạn đang làm việc cho một công ty bán lẻ cung cấp giảm giá dựa trên cấp độ thành viên: *GOLD*, *SILVER* và *BRONZE*. Code hiện tại sử dụng loop và conditions để xác định tỷ lệ giảm giá.

**Vấn đề:** Khi doanh nghiệp mở rộng và thêm các cấp độ mới, cách tiếp cận này sẽ khó bảo trì.

### Yêu Cầu

Sử dụng Amazon Q Developer để refactor, fix và optimize code.

---

### Task 1: Refactor Code

**Mở method `calculateDiscount` và sử dụng Refactor Code:**

1. Thay thế loop và conditions bằng **Enum** tên `MembershipLevel`
2. Định nghĩa mỗi cấp độ thành viên như một constant với discount rate:
   - `GOLD` → discount rate `0.20`
   - `SILVER` → discount rate `0.15`
   - `BRONZE` → discount rate `0.10`
3. Cập nhật method để sử dụng `MembershipLevel.valueOf()`

**Code gốc:**

```java
public double calculateDiscount(String level, double amount) {
    double discount = 0;
    if (level.equalsIgnoreCase("GOLD")) {
        discount = 0.20;
    } else if (level.equalsIgnoreCase("SILVER")) {
        discount = 0.15;
    } else if (level.equalsIgnoreCase("BRONZE")) {
        discount = 0.10;
    }
    return amount * discount;
}
```

**Code sau refactor:**

```java
public enum MembershipLevel {
    GOLD(0.20),
    SILVER(0.15),
    BRONZE(0.10);
    
    private final double discountRate;
    
    MembershipLevel(double discountRate) {
        this.discountRate = discountRate;
    }
    
    public double getDiscountRate() {
        return discountRate;
    }
}

public double calculateDiscount(String level, double amount) {
    try {
        double discount = MembershipLevel.valueOf(level.toUpperCase())
                                        .getDiscountRate();
        return amount * discount;
    } catch (IllegalArgumentException e) {
        return 0; // Unknown membership level
    }
}
```

---

### Task 2: Add Error Handling và Optimize

**Sử dụng Fix Code:**
- Wrap `MembershipLevel.valueOf()` trong `try-catch`
- Trong catch block, set discount về `0` nếu không nhận diện được membership level

**Sử dụng Optimize Code:**
- Review và áp dụng các tối ưu đề xuất
- Loại bỏ redundant code
- Cải thiện method calls

---
