# Amazon Q Developer - Phát Hiện Và Xử Lý Race Condition Trong Ứng Dụng Java

## Giới Thiệu

Bạn đang phát triển tính năng đăng ký khoản vay (loan registration) cho ứng dụng ngân hàng. Người dùng gửi thông tin như tên, thu nhập và số tiền vay, và ứng dụng xử lý để đánh giá tính đủ điều kiện.

**Vấn đề:** Nhiều phần của ứng dụng truy cập và cập nhật dữ liệu này cùng lúc. Hãy tưởng tượng như hai người viết trên cùng một tờ giấy cùng lúc — một người có thể vô tình ghi đè lên người kia, kết quả cuối cùng bị lẫn lộn.

Đây gọi là **Race Condition** — xảy ra khi hai hoặc nhiều phần của hệ thống cạnh tranh để cập nhật dữ liệu dùng chung (shared data) cùng một lúc.

**Hậu quả:**
- Data discrepancies (dữ liệu không nhất quán)
- Lỗi mà không có synchronization phù hợp
- Ghi đè lên nhau → sai số lượng khoản vay hoặc kết quả đánh giá

**Synchronization** đảm bảo các cập nhật xảy ra đúng thứ tự, giữ dữ liệu chính xác và ứng dụng đáng tin cậy.

## Ví Dụ Thực Tế: Loan Registration System

### Vấn Đề

Trong hệ thống đăng ký khoản vay, nhiều threads xử lý các tác vụ:
- Xác minh thông tin người dùng
- Tính toán eligibility
- Cập nhật loan counters

**Không có synchronization:** Hai threads cập nhật shared data cùng lúc có thể ghi đè lên nhau, gây sai lệch.

---

### Code Có Bug (Race Condition)

```java
public class LoanProcessor {
    private int loanCounter = 0;
    
    public void processLoan(String userId) {
        // Non-thread-safe increment
        loanCounter++;
        System.out.println("Loan processed for " + userId + 
                          ". Total loans: " + loanCounter);
    }
    
    public static void main(String[] args) {
        LoanProcessor processor = new LoanProcessor();
        
        Thread thread1 = new Thread(() -> processor.processLoan("User1"));
        Thread thread2 = new Thread(() -> processor.processLoan("User2"));
        
        thread1.start();
        thread2.start();
    }
}
```

**Vấn đề:**
- Cả hai threads có thể đọc `loanCounter` = 0 cùng lúc
- Cả hai increment lên 1 và ghi lại giá trị 1
- **Expected:** 2 loans → **Actual:** 1 loan (một update bị mất)

---

### Amazon Q Developer Phát Hiện

Amazon Q Developer xác định `loanCounter++` là vấn đề tiềm ẩn:

| Phát Hiện | Mô Tả |
|-----------|-------|
| **Shared variable access** | `loanCounter` được truy cập bởi nhiều threads cùng lúc → nguy cơ synchronization |
| **Non-thread-safe operation** | `loanCounter++` không an toàn trong môi trường đa luồng |
| **Race condition** | Cả hai threads đọc cùng giá trị (0) → increment → ghi 1 thay vì 2 |

**Ví dụ cụ thể:**

```
Thread 1: Reads loanCounter = 0
Thread 2: Reads loanCounter = 0
Thread 1: Increments to 1, writes back
Thread 2: Increments to 1, writes back
Result: loanCounter = 1 (sai, expected = 2)
```

---

### Code Đã Sửa Với Synchronized

**Đề xuất của Amazon Q Developer:** Thêm từ khóa `synchronized` vào method để đảm bảo chỉ một thread truy cập cùng lúc.

```java
public class LoanProcessor {
    private int loanCounter = 0;
    
    // Synchronized method ensures thread safety
    public synchronized void processLoan(String userId) {
        loanCounter++;
        System.out.println("Loan processed for " + userId + 
                          ". Total loans: " + loanCounter);
    }
    
    public static void main(String[] args) {
        LoanProcessor processor = new LoanProcessor();
        
        Thread thread1 = new Thread(() -> processor.processLoan("User1"));
        Thread thread2 = new Thread(() -> processor.processLoan("User2"));
        
        thread1.start();
        thread2.start();
    }
}
```

**Cách hoạt động:**
- Khi thread1 gọi `processLoan()`, nó chiếm lock
- Thread2 phải đợi thread1 hoàn thành
- Sau đó thread2 mới được cập nhật
- **Kết quả chính xác:** loanCounter = 2
